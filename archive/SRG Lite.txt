# SRG Lite — Product Design Document

## Overview

SRG Lite is a simplified research-orientation tool designed for PhD students and researchers entering unfamiliar fields.

The goal is NOT to be a full bibliography manager, graph analytics platform, or research operating system.

The goal is to help users answer one question clearly:

> “Where should I start in this research area?”

SRG Lite uses the existing backend pipeline and graph infrastructure but intentionally exposes only a minimal, guided experience.

The backend is considered frozen for this phase.
Do NOT redesign or significantly refactor backend ingestion, clustering, embedding, graph, ranking, or persistence systems unless absolutely necessary for frontend integration.

This phase is focused on:

* frontend simplification,
* workflow clarity,
* reducing cognitive overload,
* guided exploration.

---

# Core Product Philosophy

The product should feel:

* calm,
* guided,
* readable,
* opinionated,
* lightweight.

The interface should prioritize:

* understanding,
* orientation,
* reading decisions,
  not graph complexity or technical controls.

Users should never feel like they are operating a graph database or research pipeline.

---

Primary user:

* PhD student entering a new research field.

Secondary users:

* engineers exploring unfamiliar topics,
* researchers starting literature reviews.

---

# Primary User Question

> “Where should I start?”

Everything in the UI should support this question.

1. User enters:

   * topic,

# SRG Lite — Retrieval Quality & Field-Aware Discovery Phase

## Objective

Improve research relevance quality by shifting retrieval and graph construction away from generic semantic similarity and toward field-aware research relationships.

The current system over-relies on embedding similarity, causing topic drift into semantically related but research-irrelevant literature.

Example:

* Query: "Directed Preference Optimization"
* Incorrect retrievals:

  * generic optimization,
  * Bayesian optimization,
  * convex optimization,
  * support vector optimization.

The system should instead prioritize:

* citation neighborhoods,
* research communities,
* canonical papers,
* field-specific terminology,
* co-citation structure,
* recent field lineage.

---

# New Retrieval Philosophy

The system should model:

* research conversations,
  not generic semantic similarity.

Papers are considered strongly related when they:

* cite similar canonical works,
* are co-cited together,
* belong to the same citation neighborhood,
* emerge from the same research community,
* use field-specific terminology,
* appear in the same conference/journal ecosystem,
* participate in the same historical lineage.

Semantic embeddings should become a secondary refinement signal, not the primary retrieval mechanism.

---

# Retrieval Pipeline (New Direction)

## OLD PIPELINE

Query
→ embedding similarity
→ semantic expansion
→ clustering

This caused semantic drift.

---

## NEW PIPELINE

Query
→ identify anchor papers
→ build citation neighborhood
→ expand through co-citation/bibliographic coupling
→ detect research communities
→ optionally refine with embeddings
→ generate simplified topic map

---

# Phase 1 — Anchor Paper Identification

Goal:
Find highly field-relevant seed papers before broader expansion.

Possible approaches:

* exact title/alias matching,
* acronym detection,
* OpenAlex search ranking,
* Semantic Scholar ranking,
* query-to-paper reranking,
* citation count priors for canonical works.

Examples:

* "DPO" → Direct Preference Optimization paper
* "RLHF" → foundational RLHF papers
* "transformers" → Attention Is All You Need

The retrieval pipeline should strongly anchor around these papers.

---

# Phase 2 — Citation Neighborhood Expansion

Instead of broad semantic nearest-neighbor expansion:

Prefer:

* references of anchor papers,
* citing papers,
* co-cited papers,
* bibliographic coupling.

Expansion should prioritize:

* direct citation structure,
* repeated co-occurrence in literature.

This models actual research communities better than embeddings alone.

---

# Phase 3 — Community Detection

Clusters should emerge primarily from:

* citation topology,
* co-citation structure,
* bibliographic coupling,
  not abstract semantic similarity alone.

Embedding similarity may be used:

* inside already-established field neighborhoods,
* for local refinement only.

---

# Phase 4 — Drift Reduction

The system should actively penalize:

* semantically broad terms,
* generic optimization literature,
* unrelated mathematical subfields,
* weakly connected semantic neighbors.

Introduce:

* field coherence scoring,
* citation-connectedness thresholds,
* anchor-distance penalties.

---

# Field Coherence Concept

A paper should not appear highly ranked merely because:

* its abstract contains similar words.

A paper should rank highly when:

* it belongs to the same research conversation.

Signals:

* shared citations,
* common benchmark papers,
* same conference ecosystems,
* repeated co-citation patterns,
* temporal lineage continuity.

---

# Ranking Priorities

Prioritize:

1. Citation-connectedness to anchors.
2. Co-citation strength.
3. Bibliographic coupling.
4. Canonical field relevance.
5. Recent influential descendants.
6. Semantic similarity (secondary only).

---

# UI Implications

The UI should communicate:

* field branches,
* lineage,
* foundational works,
* influential descendants,
  not generic semantic similarity.

Topic branches should represent:

* actual research directions,
  not embedding neighborhoods.

---

# Important Constraints

DO NOT:

* rewrite the entire backend,
* remove existing graph infrastructure,
* remove embeddings entirely.

Instead:

* rebalance retrieval weighting,
* reduce semantic dominance,
* prioritize citation/community structure.

---

# Engineering Goal

The system should increasingly answer:

> "What papers belong to this research field?"

instead of:

> "What papers are semantically similar?"

This phase focuses on:

* retrieval quality,
* field coherence,
* researcher trust,
* reduction of semantic drift.


SRG Lite — Retrieval Repair & Citation Expansion Phase
Objective

The current system frequently returns:

a single anchor paper,
disconnected nodes,
zero citation edges,
weak or missing reference enrichment,
semantically related but field-irrelevant papers.

This prevents SRG Lite from producing:

research branches,
foundational papers,
lineage maps,
guided reading flows,
trustworthy field orientation.

This phase focuses on transforming the system from:

“semantic paper similarity”

into:

“research field neighborhood reconstruction.”

Problem Diagnosis

Current failure example:

"Directed Preference Optimization"

Observed behavior:

only one paper retrieved,
no references attached,
no citation edges,
no community structure,

This indicates the retrieval system is currently behaving like:

→ semantic match

→ stop

instead of:

SRG Fix: Directed Preference Optimization (DPO)

The initial SRG retrieval for the query “Directed Preference Optimization” produced several irrelevant or weakly related nodes due to lexical ambiguity between “Directed” and the actual method name “Direct Preference Optimization (DPO)”.

Observed Issues

The graph incorrectly expanded into:

Reinforcement learning summarization literature
Generic ranking and optimization papers
Multimodal hallucination correction works
Classical IR ranking methods
Unrelated graph hubs with high bibliographic connectivity

Examples of noisy nodes included:

RANK ANALYSIS OF INCOMPLETE BLOCK DESIGNS
Optimizing search engines using clickthrough data
Learning to rank for information retrieval

These papers appeared because the SRG expansion relied heavily on:

bibliographic coupling,
keyword overlap,
and citation neighborhood propagation.

As a result, the retrieval drifted away from the core DPO alignment literature.

Applied Fix

We introduced a query normalization and domain-constrained expansion step:

1. Acronym and canonical-name normalization

The query:

“Directed Preference Optimization”

was normalized toward the canonical method family:

Direct Preference Optimization (DPO)

This reduced semantic drift caused by token-level similarity.

2. Seed-paper anchoring

The graph expansion was anchored around highly relevant seed papers:

Direct Preference Optimization: Your Language Model is Secretly a Reward Model
Training language models to follow instructions with human feedback
Constitutional AI: Harmlessness from AI Feedback
ORPO: Monolithic Preference Optimization without Reference Model
3. Edge filtering

Low-confidence edges generated purely from:

weak abstract token overlap,
generic optimization terminology,
or shallow bibliographic coupling

were down-weighted or removed.

4. Alignment-domain restriction

Expansion was constrained to papers containing concepts related to:

preference learning,
RLHF,
alignment,
reward modeling,
policy optimization,
instruction tuning.
Result

After filtering, the SRG became substantially more coherent and centered around:

DPO-based alignment methods,
RLHF alternatives,
preference optimization variants,
and post-training alignment literature.

The revised graph reduced retrieval noise while preserving meaningful methodological connections between modern alignment techniques.


SRG Enhancement: Multi-Stage Semantic–Graph Ranking Architecture
Motivation

The current SRG pipeline demonstrates strong graph construction and literature coverage capabilities. However, evaluation on method-centric queries (e.g., “Directed Preference Optimization”) reveals a systematic issue:

Canonical papers (e.g., DPO) are not reliably ranked at the top
Graph expansion can override semantic relevance
Citation hubs may dominate final rankings despite weak query alignment

This indicates that the system over-relies on graph structure and under-utilizes semantic intent modeling.

Core Design Change

We restructure SRG into a multi-stage retrieval and ranking pipeline, where graph reasoning is explicitly decoupled from semantic relevance estimation.

Stage 1 — Hybrid Candidate Retrieval

Given a query, we first retrieve a broad candidate set using:

Dense embedding retrieval (semantic similarity)
Sparse retrieval (BM25 / keyword matching)
Optional hybrid fusion
Objective

Ensure high recall of canonical and semantically equivalent papers before any graph processing occurs.

This stage guarantees that method-defining papers (e.g., DPO) are included in the candidate pool even under:

paraphrased queries
acronym variation
minor lexical mismatch
Stage 2 — Cross-Encoder Semantic Reranking

All retrieved candidates are reranked using a cross-encoder model that jointly encodes:

(query, paper title + abstract)

Purpose

This stage enforces precise query–document alignment, capturing:

synonymy (Directed ↔ Direct)
acronym equivalence (DPO ↔ Direct Preference Optimization)
paraphrased intent
contextual relevance
Output

A ranked list of semantically grounded candidate papers.

Stage 3 — Graph Expansion (Controlled Discovery Phase)

Graph-based expansion is applied only after semantic ranking.

Key Design Principle

Graph expansion is used for discovery, not primary ranking.

We expand from top-K semantically ranked nodes using:

citation links
bibliographic coupling
co-reference structure

However, expansion is constrained by:

depth limits
edge confidence weighting
semantic relevance retention thresholds
Stage 4 — Graph-Aware Re-ranking

Final ranking is computed using a hybrid score:

FinalScore=0.7⋅SemanticScore+0.3⋅GraphScore

Interpretation
SemanticScore dominates ranking
GraphScore acts as a contextual enrichment signal

This prevents citation hubs from overriding query relevance.

Stage 5 — Anchor Preservation Mechanism

To ensure stability for method-centric queries:

Highly semantically relevant nodes are marked as anchors
Anchor nodes cannot be demoted below a minimum ranking threshold during graph propagation
Anchors act as semantic “fixed points” in the graph

This is applied dynamically and does NOT rely on hardcoded paper lists.

Expected Behavior After Fix

For a query such as:

“Directed Preference Optimization”

The system should consistently:

Retrieve and rank the canonical DPO paper:
Direct Preference Optimization: Your Language Model is Secretly a Reward Model
Follow with closely related alignment methods:
ORPO variants
RLHF baselines
reward modeling literature
Use graph expansion only to enrich surrounding context (not override ranking)
Outcome Improvements

This redesign improves:

Canonical paper retrieval accuracy
Robustness to query variation and ambiguity
Resistance to graph hub dominance
Separation of retrieval vs. exploration roles
Stability of ranking under citation-heavy neighborhoods
Summary

The SRG system is transitioned from a graph-dominant retrieval model to a semantic-first, graph-enhanced ranking system, aligning it with modern hybrid retrieval architectures used in large-scale academic search engines.

    CANONICAL_LOOKUP = "canonical_lookup"

def classify_query(query: str, context: dict) -> dict:
    """
    Returns:
    {
        "intent": str,
        "confidence": float
    }
    """

    features = {
        "has_definition_terms": detect_definition_words(query),
        "has_compare_terms": detect_comparison(query),
        "is_single_entity_query": detect_entity_like_query(query),
    }

    if features["has_definition_terms"] and features["is_single_entity_query"]:
        return {"intent": QueryIntent.CANONICAL_LOOKUP, "confidence": 0.8}

    if features["has_compare_terms"]:
        return {"intent": QueryIntent.SURVEY, "confidence": 0.7}

    return {"intent": QueryIntent.EXPLORATION, "confidence": 0.6}

def compute_canonicality(node, query, intent):
    """
    Measures whether a paper is the *definition-level source*
    rather than just graph-central.
    """

    score = 0.0

    # exact title match signal
    if query.lower() in node.title.lower():
        score += 0.6

    # citation authority signal
    score += min(node.inbound_citations / 100.0, 0.3)

    # survey / foundational mentions
    if node.is_in_survey_context:
        score += 0.2

    # intent-aware boost
    if intent == "canonical_lookup":
        score *= 1.5

    return min(score, 1.0)

def compute_final_score(node, query_context):
    intent = query_context.intent

    semantic = node.semantic_score
    graph = node.graph_score
    canonical = node.canonicality_score

    if intent == "canonical_lookup":
        weights = (0.4, 0.2, 0.4)
    elif intent == "survey_mode":
        weights = (0.4, 0.4, 0.2)
    else:
        weights = (0.6, 0.3, 0.1)

    return (
        weights[0] * semantic +
        weights[1] * graph +
        weights[2] * canonical
    )
