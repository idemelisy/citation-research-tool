# SRG Lite Roadmap — From Research Prototype to Production-Grade Research Discovery System

## Current State Assessment

SRG Lite has already evolved beyond a simple retrieval prototype. The system now includes:

* Hybrid semantic + graph-based ranking
* Intent verification and semantic alignment
* Citation graph reasoning
* Foundational paper detection
* Topic separation and clustering
* Diagnostics and provenance tracking
* Fallback semantic retrieval
* Diversity-aware normalization
* Query-conditioned retrieval passes
* Structured export generation

This places the system in the category of:

> “advanced research prototype approaching early product maturity.”

The remaining challenges are no longer primarily about “can the system retrieve papers,” but instead:

1. Ranking calibration
2. Query-specific relevance control
3. Trust consistency
4. UX coherence
5. Evaluation rigor
6. Explainability
7. Product polish

The roadmap below defines the recommended evolution path from the current SRG Lite v2 state toward a production-grade research discovery platform.

---

# Phase 1 — Ranking Correctness and Retrieval Reliability

## Target Timeline

2–4 weeks

## Goal

Ensure that the ranking engine behaves correctly across different query types and that semantic relevance consistently dominates unrelated graph popularity.

This phase is the highest priority because ranking correctness determines whether users trust the system at all.

---

# 1.1 Query-Conditioned Canonicality

## Problem

Current canonicality scoring appears globally biased toward:

* high citation count,
* graph hubs,
* older foundational papers.

This creates failure modes where:

* broad theoretical papers outrank query-specific technical papers,
* old foundational work dominates practical systems queries.

Example:
For:

> “hardware accelerated tessellation”

The system incorrectly promotes:

* general surface design papers,
  instead of:
* GPU tessellation and hardware rendering papers.

---

## Required Change

Canonicality must become query-conditioned instead of globally static.

Current implicit behavior:

score(p)=semantic(p,q)+global_centrality(p)+canonicality(p)

Desired behavior:

canonicality_{query}(p)=centrality(p)\cdot proximity(p,anchor_papers(q))\cdot intent_alignment(p,q)

---

## Implementation Tasks

### Add Query Anchor Papers

* Select top-k semantic seed papers
* Build local query neighborhood
* Use local graph proximity instead of global graph importance

### Add Anchor Distance Metric

Candidate metrics:

* shortest citation-path distance,
* co-citation overlap,
* bibliographic coupling,
* personalized PageRank.

### Add Query-Specific Centrality

Replace:

* global citation hub scoring,
  with:
* local query-neighborhood importance.

---

## Expected Outcome

The system should:

* prioritize technically relevant papers,
* reduce irrelevant foundational dominance,
* improve query specificity,
* improve top-10 precision substantially.

---

# 1.3 Semantic Drift Suppression Improvements

## Problem

Some graph expansions drift into loosely related areas because:

* graph connectivity propagates relevance,
* semantic penalties are insufficient.

---

## Required Improvements

### Hard Semantic Thresholds

Prevent papers below:

* minimum semantic similarity,
* minimum intent alignment,
  from entering top-ranked results.

### Multi-Hop Decay

Penalty should increase with:

* graph distance from anchor set.

### Vocabulary Coherence Checks

Add:

* domain keyword overlap,
* embedding neighborhood consistency.

---

## Expected Outcome

Reduced topic drift and improved retrieval coherence.

# 2.1 Cluster Labeling System Rewrite

## Problem

Incorrect cluster labels destroy trust instantly.

Example:

> “General Preference Alignment”
> appearing inside a graphics query.

This suggests:

* topic leakage,
* stale taxonomy reuse,
* cached labels from unrelated domains.

Even if retrieval quality is high, this damages credibility.

---

## Required Changes

### Remove Shared Global Label Pools

Cluster labels must be:

* generated per-query,
* generated per-cluster,
* context-dependent.

### Generate Labels Dynamically

Potential methods:

* TF-IDF keyword extraction,
* KeyBERT,
* cluster centroid embeddings,
* LLM-assisted labeling.

### Add Domain Sanity Checks

Prevent:

* NLP labels inside graphics queries,
* biology labels inside systems queries.

---

## Expected Outcome

Users perceive:

* coherence,
* topical understanding,
* system intelligence.

---

1.1 Query-Conditioned Canonicality (MANDATORY)
File:

canonicality.py

New Function:
compute_query_conditioned_canonicality(paper, query_context)
Formula Components:

Canonicality is now:

final_canonicality =
    base_canonicality
  + anchor_proximity_factor
  + semantic_alignment_score
  + vocabulary_coherence_score
  - recency_penalty_decay (if outdated for query type)
Anchor Proximity (NEW CRITICAL SIGNAL)
anchor_proximity_factor(hops)

Rules:

hops = graph distance from query anchor papers
weighting:
hops = 1 → +1.0
hops = 2 → +0.6
hops = 3 → +0.3
hops > 3 → 0.0

👉 MUST override raw citation dominance when conflict exists.

Integration Rule:

In:

lite_v2_ranking.py

Replace:

canonicality_score = base_canonicality

With:

canonicality_score = compute_query_conditioned_canonicality(...)
